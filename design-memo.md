My linked list works by storing each customer inside a Node. Each Node has the customer’s name and a next pointer that connects it to the next customer in the waitlist. The LinkedList class keeps track of all the Nodes and has methods for adding someone to the front, adding someone to the end, removing someone, and printing the full waitlist. When someone is added to the front, the new Node becomes the first Node. When someone is added to the end, the program moves through the list until it finds the last Node and connects the new one to it.

The head is important because it points to the first Node in the linked list. It is basically the starting point for the whole waitlist. If the head is None, then the waitlist is empty. The head also has to change when a new customer is added to the front or when the first customer is removed.

A real engineer could use a custom list like this when they need more control over how data is stored and changed. For example, a ticket company could use something similar for a customer waitlist where VIP customers can move to the front. A custom linked list can also be useful when the number of customers changes a lot because Nodes can be added or removed without needing to rebuild the whole list.
